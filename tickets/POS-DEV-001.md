# POS-DEV-001 — Device-Generated Activation Code

**Category:** POS DEVICE ACTIVATION

**Scope:** POS App + Backend

---

## Implement

- When POS app is unbound:
  - Generate short activation code (e.g. `SM-A7K2-91`)
  - Code is:
    - single-use
    - time-limited (10–15 min)

- Store activation codes in DB with:
  - device fingerprint
  - expiry
  - used_at
  - bound store_id

---

## Acceptance

- [ ] Code cannot be reused
- [ ] Code cannot bind multiple stores
- [ ] Code auto-invalidates after binding

---

### Current flow summary:

**Existing Enrollment System (`backend/src/routes/v1/pos/enroll.ts`):**
- Enrollment codes are **store-generated** (not device-generated)
- Code format: 8-character alphanumeric (e.g., `ABC12345`)
- Stored in `pos_device_enrollments` table
- Supports multi-use codes (demo mode: max_uses=9999)
- Device fingerprint used for idempotency

**Database Tables:**
- `pos_device_enrollments` — enrollment codes
- `pos_devices` — enrolled devices with tokens

**Current Code Properties:**
| Property | Current | Plan |
|----------|---------|------|
| Generated by | Store (SuperAdmin) | Device |
| Format | 8 chars alphanumeric | `SM-XXXX-XX` |
| Expiry | No expiry | 10-15 min |
| Single-use | Configurable (max_uses) | Always single-use |

### Gaps vs plan:

- [ ] **Device-generated**: Currently codes are admin-generated, NOT device-generated
- [ ] **Code format**: Current is `ABC12345`, plan is `SM-A7K2-91`
- [ ] **Time expiry**: No expiry currently — codes last forever
- [ ] **Single-use enforcement**: Currently uses `max_uses` counter, not strict single-use
- [ ] **Flow reversal**: Plan requires device to generate code, web to enter it (opposite of current)

### Retailer Dashboard already covers part of this ticket?

**NO** — Current flow has Retailer Dashboard entering code generated by SuperAdmin. This ticket reverses the flow: POS generates code, Retailer Dashboard enters it.

### B.2) API Subtickets

#### B.2.1) Device Code Generation
- [ ] **POS-DEV-001-API-GEN**: `POST /api/v1/pos/generate-activation-code`
  - File: `backend/src/routes/v1/pos/enroll.ts`
  - Request: `{ device_fingerprint: string }`
  - Response: `{ code: "SM-A7K2-91", expires_at: "ISO timestamp" }`
  - Generate format: `SM-[4 alphanum]-[2 alphanum]`
  - Store with 15 min expiry
  - Invalidate any existing code for this fingerprint

#### B.2.2) Code Validation & Binding
- [ ] **POS-DEV-001-API-BIND**: `POST /api/v1/retailer-admin/activate-device`
  - File: `backend/src/routes/v1/retailer-admin/devices.ts` (NEW)
  - Request: `{ activation_code: string }`
  - Validates:
    - Code exists
    - Code not expired
    - Code not already used
  - On success:
    - Mark code as used
    - Create device record
    - Bind device to current store
    - Update store status (if DRAFT → ENROLLED)
  - Response: `{ device_id: string, store_id: string }`

#### B.2.3) Code Status Check
- [ ] **POS-DEV-001-API-CHECK**: `GET /api/v1/pos/activation-status/:fingerprint`
  - File: `backend/src/routes/v1/pos/enroll.ts`
  - Called by POS to poll if code was used
  - Response: `{ status: "pending|activated|expired", device_id?: string, store_id?: string }`

### B.3) DB/Migration Subtickets

#### B.3.1) Schema Changes
- [ ] **POS-DEV-001-DB**: Create device_activation_codes table
  - Migration: `070_device_activation_codes.sql`
  ```sql
  CREATE TABLE IF NOT EXISTS pos.device_activation_codes (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    code VARCHAR(12) UNIQUE NOT NULL,  -- SM-XXXX-XX format
    device_fingerprint VARCHAR(255) NOT NULL,
    expires_at TIMESTAMPTZ NOT NULL,
    used_at TIMESTAMPTZ,
    bound_store_id UUID REFERENCES platform.stores(id),
    bound_device_id UUID REFERENCES pos.pos_devices(id),
    created_at TIMESTAMPTZ DEFAULT NOW()
  );

  -- Index for code lookup
  CREATE INDEX idx_activation_codes_code ON pos.device_activation_codes(code);

  -- Index for fingerprint (to invalidate old codes)
  CREATE INDEX idx_activation_codes_fingerprint ON pos.device_activation_codes(device_fingerprint);

  -- Cleanup old expired codes (can be run periodically)
  -- DELETE FROM pos.device_activation_codes WHERE expires_at < NOW() - INTERVAL '1 day' AND used_at IS NULL;
  ```

```bash
# Try expired code (wait 15+ min)
# Expected: 400 { "error": "Code expired" }
```
