# RET-POS-001 — Replace Enrollment-Only Screen with Retailer Onboarding

**Category:** RETAILER ONBOARDING — POS FLOW (PRIMARY)

**Scope:** POS App

---

## Implement

On fresh POS install show **Retailer Sign-In / Register wizard**:

### Step 1 — Store & Owner Details

- Store name
- Location + full address
- Store type:
  - Grocery
  - Kirana
  - Supermarket
  - Other → **required "Specify other store type"**
- GSTIN
- Authorized person name
- Phone (OTP)
- Email

### Step 2 — Document Upload

- Aadhaar
- GST certificate
- Owner selfie

### Step 3 — Payments

- UPI address (mandatory)
- Bank details (optional initially)

---

## System Action

- Auto-create store
- Auto-bind device
- Set status → `ENROLLED` + `KYC_SUBMITTED` + `PAYMENTS_SUBMITTED`

---

## Acceptance

- [ ] No manual enrollment code required
- [ ] POS opens in LIMITED MODE after submit

### Current flow summary:

**POS App (`src/` - React Native/Expo):**
- Current flow: Device enrollment via code entry
- No full onboarding wizard exists
- Screens: `EnrollmentScreen` for code entry only
- No document upload in POS currently
- No UPI collection in POS currently

**Current Enrollment Flow:**
1. User opens POS app
2. Enters enrollment code (generated by SuperAdmin)
3. Device binds to existing store
4. App enters operational mode

**Missing from current POS:**
- Store registration form (store doesn't exist yet)
- Owner details collection
- Document upload capability
- UPI address collection
- OTP verification for phone

### Gaps vs plan:

- [ ] **No registration wizard**: POS only has enrollment (existing store), not registration (new store)
- [ ] **No document upload**: POS doesn't collect Aadhaar, GST, selfie
- [ ] **No UPI collection**: UPI only in web dashboard
- [ ] **No OTP in POS**: Phone OTP verification not implemented
- [ ] **Store types**: Not collected in POS
- [ ] **Address**: Only basic location, not full address

### Retailer Dashboard already covers part of this ticket?

**PARTIALLY** — Retailer Dashboard has store registration (`RegisterPage.tsx`), but:
- Missing: Aadhaar upload, GST certificate, owner selfie
- Missing: Store type selection with "Other" specification

### B.2) API Subtickets

#### B.2.1) Store Registration Endpoint
- [ ] **RET-POS-001-API-REG**: `POST /api/v1/pos/register-store`
  - File: `backend/src/routes/v1/pos/registration.ts` (NEW)
  - Request:
    ```json
    {
      "store_name": "string",
      "address": "string",
      "location": { "lat": number, "lng": number },
      "store_type": "Grocery|Kirana|Supermarket|Other",
      "store_type_other": "string (if Other)",
      "gstin": "string",
      "owner_name": "string",
      "phone": "string",
      "email": "string",
      "device_fingerprint": "string"
    }
    ```
  - Response: `{ store_id: string, status: "ENROLLED" }`
  - Creates store in ENROLLED state
  - Auto-binds device to store

#### B.2.2) Document Upload Endpoint
- [ ] **RET-POS-001-API-DOCS**: `POST /api/v1/pos/upload-documents`
  - File: `backend/src/routes/v1/pos/registration.ts`
  - Multipart form data: aadhaar, gst_certificate, owner_selfie
  - Stores in cloud storage (GCS/S3)
  - Updates store: kyc_complete = true, status = KYC_SUBMITTED

#### B.2.3) Payment Setup Endpoint
- [ ] **RET-POS-001-API-PAY**: `POST /api/v1/pos/setup-payments`
  - File: `backend/src/routes/v1/pos/registration.ts`
  - Request: `{ upi_address: string, bank_details?: { account, ifsc, bank_name } }`
  - Validates UPI format
  - Updates store: upi_complete = true, status = PAYMENTS_SUBMITTED
