## Pre-Existing Bugs Found During Testing

During local-prod testing, two pre-existing bugs in `supplierStateMachine.ts` were found
and fixed (these affect ALL status transitions, not just SA-P1-005 suspension):

1. **Postgres type inference**: `$2` parameter used in both SET and CASE expressions caused
   "inconsistent types deduced for parameter $2". Fix: cast to `$2::text`.

2. **UUID column vs string adminId**: `status_updated_by` and `verified_by_user_id` are UUID
   columns, but legacy admin token sets adminId to "master-token" (not a UUID).
   Fix: CASE expression to only set when value matches UUID pattern.

Both fixes are in the same `transitionSupplier()` function and will need to be included
in the PR push.
